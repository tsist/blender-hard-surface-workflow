# 建模过程的保存与精准回退

## 什么时候保存整模

| 时机 | 保存什么 | 下一次如何接续 |
| --- | --- | --- |
| 开工或 GUI 接手 | 记录只读来源的绝对路径、SHA-256、Blender 构建、插件版本与外部资源。使用一个当前工作件。 | 同一分支记录父文件及作业 ID，有多个同形零件时记实际对象、Mesh 与地标。 |
| 普通调参、选区或机位预览 | 在工作件中操作。把同一目的且可重放的动作合并进一个 manifest。记录请求、操作索引、关键尺寸及必要的一个局部视图。 | 已有 CLI 候选可以直接当作锚点，记录其路径与 SHA。无需为每个视图、步骤或交接目录再复制整模。 |
| 应用修改器、删减母面、不可重放的刀切、长模态或跨入口交接 | 在动作前确认最近通过的锚点能独立重开，且含要保护的几何与依赖。若自该锚点后有无法从记录恢复的手改，为当前状态保存一个结构锚点。GUI 交给 CLI 前先保存工作件并更新 SHA。 | 按[硬表面审核规程](geometry-topology-acceptance.md)通过布线、流形、实际效果以及该阶段应验的装配和固定区，再更新“最近通过”的指向。CLI 作业中用于恢复的源和原候选按原路径保留。 |
| 返工与发布 | 每个正在制作的部件默认同时维护**一个当前工作件、一个最近通过的结构锚点**；只读源另计。若两者或锚点与源为同一文件，只记一次。保留特定旧工序的点回退能力、已交付版本或不可复现的手工里程碑时，加登记具名例外。 | 以路径引用现有文件。新候选验收时需临时共存；在原任务已授权的工作件上原位保存。既有文件需要淘汰时先出清单、核依赖并取得清理授权。 |

一条工序记录至少包含父路径和 SHA、工序索引/意图、对象及表示层（源笼或求值）、真实选区和保护区、单位/空间、请求参数、版本、验收结果与候选位置。孔写设计孔心和通径，折边写相对谁的位移。记录“形体何时第一次偏离”，能直接定位重放的截止位置。

每条活动分支默认只开**一个待验候选**。下一次准备另存或再次提交作业前，先查同一父 SHA、请求与工具版本是否已有可用候选。已通过就把原路径登记为锚点；失败作业保留轻量回执。如果旧候选仍占用保留名额且需要新整模，先列出占位、大小、引用者和替代路径，决定复用、获准轮换或为有用分支单列预算。不要靠连续更名绕开名额。以后要逐点反演的工序须保留该作业原输入和输出并计入预算，轮换时同时更新可恢复范围。

**面板与批处理的保存开销不同。** `model panel-controls` 的绑定目标、选工具、配置参数、进入编辑模式、生成预览、执行会分别写候选。需要接手一个人已保存的预览时，从现有文件做只读 `inspect-preview`，直接复用回执里的执行请求。在纯 agent 建模中，同一目标的多道已知操作可用一份 `model prepare` 清单生成一个候选。预算要包括作业目录、候选、自动备份及短时共存，按 Blender 单个动作拆分前先估算。前缀重放应核对原作业与当前硬表面版本；旧回执没有记录版号时，从当时的交接记录补证，再复测接合处。`面板保存交接实测`

一个工程内复制很多 Scene 或独立 Mesh 同样增加存储。多个 Scene 共享同一 Mesh 时，编辑会传到其他使用者。保留一个已验证的原始锚点及可复现工序，比用场景名猜哪个版本可以回退可靠。依赖还包括链接库、贴图序列、UDIM、缓存和工具版本。按已识别的资源清单运行 `project verify`，同时核实项目专用缓存。[公共 CLI 的依赖核验用法](https://github.com/tsist/blenderctl/blob/main/skills/blender-cli/references/execution.md)

单一对照工程可以为 A、B 各留一个场景，共用固定零件，只给改动对象及其切刀独立数据。复跑默认在内存执行，显式指定新目标时才另存。审核交接锁定一个 SHA，分场景复测并核固定对象指纹。常规出图复用图证目录，整模留在原路径。 `二级四件的 A/B 保存实证`

## 选择回退方式

| 意图 | 入口与边界 |
| --- | --- |
| 回到一批操作中某道工序之前 | [按工序回退](../scripts/plan_step_rewind.py)。从原作业的只读父锚点重放该工序前的连续前缀。新分支会舍去其后所有工序；后续仍需要的编辑须重新定位、复核后再接回。 |
| 在当前手调版上只撤回一个或几个错点 | [按顶点回退](../scripts/plan_vertex_rewind.py)。三方比较当初源笼、旧成功候选、明确同分支的当前已保存工程。只生成指定点的反向坐标请求。 |
| GUI 手改无工序记录、切错拓扑或同点有后改冲突 | 先保当前手调，从最近可冷开的结构锚点分支，重新做出错段。GUI 会话仍在时可以查看撤销历史。恢复自动保存文件前先保护正在打开的工作。 |
| 撤销一次已发布文件替换 | 先核 `transaction status`，使用对应 ID 的 `transaction rollback` 恢复该笔发布前的目标。发布前用 `project plan-files` 核目标、备份及依赖，获具体覆盖授权后再 `transaction apply`。后续改过目标会发生冲突，保住两边再决定。中断的流水线用 `pipeline resume` 接续。`文件事务的可恢复范围` |

### 按工序回退

以下命令使用本项目的 Blender 5.3.0 和公共 CLI。将输出放在原作业目录之外的现有工作目录。先列工序，对照原始 `request.json` 的对象、选区与参数。索引从 **0** 开始，`--before-index 2` 表示保留第 1、2 道，排除第 3 道及之后的操作。

```powershell
$project = '<PROJECT_ROOT>'
$blender = Join-Path $project 'runtime/blender/releases/5.3.0/blender-5.3.0-windows-x64/blender.exe'
$py = Join-Path (Split-Path -Parent $blender) '5.3/python/bin/python.exe'
$scripts = Join-Path $project '.agents/skills/blender-hard-surface-modeling/scripts'
$ctl = Join-Path $project 'blenderctl.ps1'
$job = '<原 model.prepare 作业的绝对目录>'
$current = '<当前已保存工作件的绝对路径>'
$request = '<本次工作目录>/before-step-3.json'
$jobs = '<本次作业的绝对目录>'
& $py -X utf8 (Join-Path $scripts 'plan_step_rewind.py') $job
& $py -X utf8 (Join-Path $scripts 'plan_step_rewind.py') $job --before-index 2 --current $current --output $request
if ($LASTEXITCODE -ne 0) { throw '回退计划未通过' }
& $ctl --blender-version 5.3.0 --jobs-dir $jobs request $request
```

成功作业且有当前工作件时传 `--current`。当前 SHA 若与旧候选不同，先保护后来手改。明确要从历史锚点另起一支时可省略它。失败作业从原始可信 job 读 `model-actions.json`，只允许已记成功的前缀；失败日志记录操作类型与顺序，单靠它不能证明事后改过的请求参数。缺父锚点的从零构造或缺终态回执的作业需回到原始配方或冷开锚点。

索引 0 会生成 `model.inspect`，直接读取父锚点，新增整模数为零。相同请求重复**规划**不会再写一份文件。重复**执行**非空 `model.prepare` 会另建 job 和完整候选，先查已有返回值和候选 SHA。使用原 Blender 和插件构建并核对外部资源。若保留的上下文依赖已排除步骤才创建的对象，需先重新建立该阶段真实上下文。重放后以几何和保护区验收，并重新取得索引与拓扑指纹；同形网格可以有不同元素编号。`五步作业的冷开实证`

### 按指定顶点回退

沿用上面的 `$blender`、`$scripts`、`$ctl` 和 `$jobs`。这里的 `$job` 须为当时**只有一条显式索引** `mesh.positions` 的成功作业，`$current` 是已核实来源的当前同分支工作件。下面只处理旧操作中的索引 0。省略 `--indices` 会检查该操作全部点。

```powershell
$request = '<本次工作目录>/restore-point-0.json'
& $blender --background --factory-startup --disable-autoexec --python-exit-code 1 --python (Join-Path $scripts 'plan_vertex_rewind.py') -- --job $job --current $current --output $request --indices 0
```

仅当上条退出为零且本次返回 `request_created` 或 `request_already_present` 时，将该请求交给 `& $ctl --blender-version 5.3.0 --jobs-dir $jobs request $request`。若该请求已有验收过的候选，直接复用。返回 `already_restored` 就结束。返回 `conflict` 或 `unverified` 时查看三方坐标或拒绝原因，停止本次执行，避免误提交目录里旧的请求。

该工具用于本地、自包含、静态单用户源笼，允许至多一个原生 Subdivision Surface。形态键、顶点组、共享、其他修改器和无法核验的依赖会被拒绝。当前点仍等于旧步骤写入值才恢复；等于原值则略过；第三种值保留并报冲突。比较的是已保存的局部坐标和有序拓扑。后来移走又移回同一坐标的意图，以及重建同名同拓扑模型的来源，需要工序记录辨认。细分表面会随源点重新求值，验收要同时看控制笼和最终形状。`普通及细分网格的实际回退`

## 每个卷怎么预算

对工作件、CLI jobs、事务暂存、Blender 临时目录及外部缓存所在的每个卷分别计算。**预计峰值占用 = 已有占用 + 同时存在的新候选及锚点 + 暂存/备份 + 审计/缓存增长 + 其他并发写入**。使用当前可用空间比较时，只减后四项，再留工作余量。下一次保存或打包的峰值加该卷预留超过可用空间时，暂停新增整模和并发作业，先复用已有候选、减低预览输出或调整有空间的授权工作位置。预留应考虑素材和失败重试的实际增长。

实测 Xbox 制作目录有 164 个已压缩的 `.blend`，合计 49.97 MiB，文件长度全部不同，`.blend1` 为 0。全目录占 587.17 MiB。另一个面板批次的 jobs 占 23.69 MiB，其中每个 job 留下的发行包合计 21.56 MiB。因此还要预算审图、发行包与失败作业。举例用 Xbox 最大快照 1,196,483 B 的两倍估算每份；若明确要求保留十个阶段，再加一个候选及一份暂存，F 盘预计新增 **27.39 MiB**。再计一份按实测最大作业两倍估算的面板 job 是 **30.23 MiB**，图像、贴图和缓存另计。此例的十阶段是演算条件。`盘点与计算依据`

本机 portable 5.2.1 配置实读为压缩开启、Save Versions 为 1、临时自动保存间隔 2 分钟。普通覆盖保存可能产生 `.blend1`，连续“另存为”仍会逐份累积。Undo、`.blend1` 和临时自动保存用于短期救援。保留现有全局偏好，控制本项目新产生的候选和预览数量。清理既有文件前先做只读清单，列全路径、字节数、相同内容的 SHA、被哪些工序/锚点/回执引用、确认可恢复的替代路径，获得授权再处理。相同 SHA 的两条路径仍可能分别承担恢复职责。`存储清单`
